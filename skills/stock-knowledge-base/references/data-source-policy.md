# 数据来源与核验规则

## 总原则

- 必须区分事实、推断和主观判断。
- 不能把市场传闻写成事实。
- 不能用记忆编造最新行情、财务、公告、监管状态。
- 无法确认的信息写 `待核验`。
- 已过期的信息标注 `stale` 或在对应字段写明数据日期。
- P1/P2 的关键结论必须记录来源。

## P0 数据要求

P0 可使用可靠基础资料源，至少核验：

- 股票代码和名称。
- 交易所和板块。
- 所属行业。
- 主营业务简述。
- 特殊状态：ST、停牌、退市风险、次新。

P0 不强制核验实时行情、完整财务和估值。

## P1 数据要求

P1 必须核验：

- 主营业务和收入结构。
- 题材/概念依据。
- 核心财务指标。
- 总市值、流通市值、PE/PB/PS。
- 近阶段交易特征。
- 主要风险标签。

题材相关度必须给出依据。没有公告、财报、互动、新闻或订单支撑时，不得标为硬逻辑。

## P2 数据要求

P2 必须核验：

- 多头逻辑和空头逻辑。
- 核心催化和兑现路径。
- 重大事件流水。
- 同题材可比公司。
- 产业链上下游。
- 技术关键位和交易特征。
- 禁入条件、触发关注条件、逻辑证伪条件。

P2 结论中涉及行情、公告、财报、监管问询、减持、重组、中标、订单的内容必须写明来源和日期。

## 推荐来源类型

优先使用：

- 交易所公告。
- 巨潮资讯、公司公告、定期报告。
- 东方财富、同花顺、证券时报、财联社等可回溯行情或资讯页面。
- 公司官网、投资者关系资料。
- 互动易、上证 e 互动等投资者问答，需标注为互动平台信息。

谨慎使用：

- 自媒体总结。
- 没有来源链接的题材列表。
- 只描述市场情绪的帖子或传闻。

## 来源记录格式

在个股卡 frontmatter 元数据区的 `sources` 中记录简短来源列表；在正文关键结论旁写来源摘要。

示例：

```yaml
sources:
  - "2026-06-22 巨潮资讯：2025年年度报告"
  - "2026-06-22 东方财富：行情与估值数据"
```

正文示例：

```md
- 题材依据：公司 2025 年年报披露相关业务收入，数据截至 2026-06-22，来源：巨潮资讯。
```

## 禁止事项

- 不输出确定性买卖指令。
- 不写“必涨”“必跌”“稳赚”等确定性表述。
- 不把未经确认的传闻写入事实字段。
- 不因为股票热门就自动标为硬逻辑。
- 不覆盖旧事件流水；只能追加新事件或更新最近复核结论。
