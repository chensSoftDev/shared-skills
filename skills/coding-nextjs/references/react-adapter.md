# 业务对象接入React

## 实例与生命周期

业务对象的职责与状态规则遵从 [前端架构](../../design-frontend-architecture/SKILL.md)。这里仅定义React连接：

- 按任务／实体／工作区创建稳定实例，由明确的容器或Provider持有；只在需要共享的范围提供同一对象。普通render不得反复new后丢失状态，也不把可变业务对象放模块级全局。
- 明确实体切换时用key重建还是复用并显式切换；保活页签按业务保留实例，关闭／登出释放。useMemo不是资源生命周期保证，构造器保持纯净，无订阅、请求、定时器或外部写入。
- I/O连接与订阅在受控生命周期建立，清理取消订阅／请求／定时器；StrictMode的挂接→清理→再次挂接安全，不因一次模拟清理永久废掉仍在使用的实例，也不产生重复业务副作用。
- SSR对象逐请求隔离；服务端传DTO或快照，客户端按契约恢复对象，不跨边界传类实例或共享用户数据。

## 响应式协议

使用项目已有对象适配能力，或在适用时使用useSyncExternalStore；不为本需求自动引入状态库。external store的subscribe返回取消函数，getSnapshot在无逻辑变化时返回同一稳定引用，变化后生成新不可变投影；按SSR契约提供稳定server snapshot。订阅／回调身份稳定，避免每render反复注册。

不可变领域对象本身若无subscribe，由持有它的任务对象／适配store发布当前实例变化，不能直接当完整external store。可变对象也必须有通知协议：直接改字段再期待React自动刷新无效。对象只读快照不能泄露可变嵌套引用；每次getSnapshot都创建新对象也会产生无意义更新或循环。

Hook只负责稳定实例、订阅、框架资源清理及UI映射。addLine、calculateQuote、submit、restore等规则和流程调用对象命令，不在Hook／组件再写一份。发布逻辑有清晰错误策略，不能把观察者渲染失败包装成已经提交的业务命令失败。

## 表单、路由、缓存与错误

- 先按架构规范确定唯一事实源。业务草稿归对象时，Form从快照渲染并发送业务命令；临时非法原始文本归Form时，在明确校验／提交边界形成领域对象。禁止同义草稿在Form、useState、对象与全局store间双写同步。
- URL管理已生效可分享条件，输入草稿另有语义；路由适配器通知任务对象加载或切换。按项目确认的查询／返回／保活规则保留状态，不在业务对象里操作router。
- 复用请求／缓存层，经小端口注入；不要把全部远端数据复制进对象再另建缓存。明确加载、失效、旧响应身份和保存结果不确定性；订阅失败不会清空业务草稿。
- 对象返回的字段／业务错误在UI映射为字段、提示或恢复入口；同一错误明确一个提示／上报者。Error Boundary只处理适用渲染子树异常，事件／异步命令的错误显式处理；失败与空列表分开。

## 验证

对象规则在无React环境测试；适配层验证实例不随重渲染重建、切实体隔离、StrictMode重复连接、取消订阅、快照稳定与更新、SSR隔离、迟到请求、失败保留草稿和恢复。实际界面任务及视觉检查交由 [frontend-ui-quality](../../frontend-ui-quality/SKILL.md)。
