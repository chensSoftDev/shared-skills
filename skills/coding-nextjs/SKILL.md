# 前端代码设计规范

## 角色

以前端架构师视角明确职责、依赖、状态与失败路径，并检查用户实际看到和操作的界面。适用于新增和实质修改的代码；按业务复杂度选择设计手段，保留有效行为，不扩大为全仓重构。

## 上下文与配置

先读消费项目 AGENTS.md 和 `.agents/skills-config.json` 的 `coding.nextjs`：

| 配置 | 用途 |
|---|---|
| `paths` | 应用角色与路径，兼容项目既有结构 |
| `conventions` | 设计文档、Token、后台专属规范、组件库、国际化、环境来源、请求入口等项目差异 |
| `verifyCommands` | 项目提供的检查命令，按实际影响选择 |

保留已有键；新增约定均可选。配置不全时从 AGENTS、目标应用 package.json 和邻近代码确认事实，必要时指出缺口；不推定应用名、语言、API 地址、组件库或框架版本。文档／源码路径相对消费项目根目录解析；本文 `references/` 相对本 skill 解析。确认配置引用存在，冲突时按项目文档权威处理。

编写或修改代码前必读 [references/design.md](references/design.md)，按改动选择相关章节；该文档是设计决策与正反例的规范正文。

## 约束

- 页面组织、业务编排、展示交互、数据访问各有职责；抽离围绕业务语义与变化原因，不以行数或机械去重代替设计。
- 面向对象思维体现在职责、封装、公开接口及组合。优先函数组件、Hook 和纯函数；领域模型确有状态不变量时可用类，不强制类组件、继承体系或万能 Hook。
- 每类状态明确唯一事实源、所有者、更新／重置／失效时机；处理请求竞态，失败保留有效输入。前端权限控制配合后端鉴权，不承担最终授权。
- API、表单与展示类型按边界建模；外部数据做必要运行时校验，禁止用 `any` 或强制断言掩盖契约问题。
- 错误按字段、业务、网络和渲染边界处理；禁止吞错或把失败伪装成空数据／成功。渲染 Error Boundary 不负责替代事件和异步请求的错误处理。
- UI 变更先读配置指定的设计文档、Token 和适用的专属规范及已确认需求；沿用公共组件。通用原则在本 skill、项目风格在设计规范、业务任务流程在需求 UX 产物维护。
- API 基址、站点域名和环境差异使用项目配置入口；服务端密钥不得进入客户端代码或公开环境变量。设计 Token、语言和字段约束遵从项目配置。
- 删除等不可逆操作按项目交互规范提供显式确认；已确认文案、布局或流程存在问题时说明影响并提出建议，涉及决定变更时走项目确认机制，不擅自重设计。

## 工作流

### 1. 识别边界

输入需求及目标应用，读配置、邻近实现、调用方和 API 契约；列出组件、业务规则、状态来源与 UIUX 影响，输出变更范围及现有可复用能力。

### 2. 设计最小结构

按设计参考明确模块公开接口、依赖方向、类型转换、状态所有者、错误处理与恢复；说明抽离解决的具体变化或复杂度。简单场景保持局部结构，复杂页面先分职责再提公共抽象。

### 3. 实现与检查体验

按已确认设计实现任务主路径及加载／空态／失败／重试；检查真实数据下的文案、层级、重点、表单和操作流程。公共组件缺陷在公共层修正，并检查相关调用方。

### 4. 验证与交付

按影响运行项目检查命令；对关键状态迁移、请求竞态和失败恢复做有意义验证。涉及 UI 时在浏览器检查真实视口、长内容、键盘／焦点和任务流程，并遵守项目视觉验收门禁。输出修改边界、验证结果及未验证项；静态检查不代表视觉或交互通过。

## 输入与输出

输入：功能、Bug、重构或界面反馈，以及项目配置与已确认方案。输出：职责和状态清楚、错误可恢复、界面符合设计依据的变更及真实验证结果。

## 自检

- [ ] 应用与配置来源正确，设计文档路径有效；框架版本来自项目事实。
- [ ] 组件／业务／数据访问边界和公开接口清楚，抽象有实际用途。
- [ ] 类型、状态事实源、请求竞态、缓存失效与表单恢复已明确。
- [ ] 错误分层处理，未吞错、泄露内部信息或重复提示。
- [ ] 文案／样式、信息结构／重点、交互流程与已确认规范一致。
- [ ] 项目 Token、语言、环境与不可逆操作约束已遵守。
- [ ] 检查和浏览器验证有真实记录；缺口明确。
