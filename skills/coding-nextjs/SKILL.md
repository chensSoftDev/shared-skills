# Next.js／React实现规范

## 角色与上下文

负责框架集成与UI适配，业务架构、状态规则和界面体验分别由独立skill维护。读取项目AGENTS与skills-config的coding.nextjs（paths、conventions、verifyCommands），框架版本读目标package.json；项目路径相对消费项目根。缺配置从真实项目识别，不推定组件库、语言、地址或新增依赖。

## 按改动加载

| 改动 | 必须读取 |
|---|---|
| 业务规则、业务状态、请求／保存流程、抽象与对象 | [design-frontend-architecture](../design-frontend-architecture/SKILL.md) |
| 对象接入React、Hook、表单、路由或Server/Client | [React适配规范](references/react-adapter.md) |
| 可见文案、样式、信息结构、页面／任务交互 | [frontend-ui-quality](../frontend-ui-quality/SKILL.md)及项目设计依据 |

多个范围同时适用时组合加载。不要在本入口复制其他skill的规范正文；简单静态样式修正无需强行加载全部业务建模材料。

## 约束

- React视图使用函数组件与组合；纯TS业务对象集中业务规则，Hook负责实例／订阅／框架生命周期适配，不重新实现规则，也不要求类组件继承。
- 按实际框架能力划分Server/Client，优先在可用服务端边界完成服务端工作；只将需要浏览器交互的区域放客户端，不默认整页use client。跨边界传可序列化DTO／快照，不传业务对象实例、凭据、数据库对象或服务端模块。
- API基址、站点地址、认证与请求入口来自项目配置；服务端密钥不进入客户端或公开变量。沿用现有请求能力和缓存机制，业务对象经端口使用它们。
- 设计文档、Token、组件库、语言／字段和本地化约定来自项目配置，引用须真实有效。复用公共组件和语义Token；删除等不可逆操作按项目规范显式确认。
- 组件PascalCase，Hook以use开头，props与事件表达语义；不导出任意业务setter或可变全局对象给视图。

## 工作流

1. 确认应用、版本、配置和调用方，按表加载适用规范，明确本次框架适配范围。
2. 稳定业务实例与事实源，连接路由／表单／缓存／错误边界；遵守React适配规范与已有组件契约。
3. 对接口、对象命令与UI效果逐项核对，按影响运行项目检查；UI另执行真实浏览器验证。
4. 输出实现、状态／对象边界及证据，未测项明确记录；构建不替代视觉或交互验收。

## 输入与输出

输入：Next.js／React实现任务与项目配置。输出：符合业务对象、框架边界及已确认UI规范的代码和真实验证。

## 自检

- [ ] 按影响加载独立规范，配置及文档路径正确。
- [ ] 对象实例与快照稳定、订阅成对清理，Hook保持适配职责。
- [ ] Server/Client、序列化、环境及认证入口安全。
- [ ] 表单／URL／缓存不复制同义事实，失败可恢复。
- [ ] 检查和适用浏览器验证有真实记录。
