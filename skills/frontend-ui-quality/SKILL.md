# 前端界面与交互质量

## 角色与上下文

产品／设计形成方案，前端负责正确实现和质量检查。读取消费项目AGENTS、skills-config中已有设计文档／Token／专属UI规范及当前获确认需求；缺配置时按真实项目事实定位，文档路径相对消费项目根。不引入固定应用、语言、尺寸、颜色或按钮文案。

## 检查矩阵

产品／设计形成方案，前端负责实现与质量检查。通用原则不能覆盖项目已确认偏好；存在冲突时提出具体问题与建议，改变已确认布局、流程或文案按项目机制处理。

| 方面 | 检查方法与合格表现 |
|---|---|
| 任务与信息结构 | 明确用户、对象、目标、入口与结果；按任务组织区块，减少重复上下文、无业务价值介绍与内部实现说明 |
| 重点与层级 | 主要操作及关键状态可发现；位置、字重、留白与语义色共同表达层级，避免全部同权重或过度强调 |
| 文案与文字样式 | 标题／标签／状态使用一致业务术语；按钮表达操作结果且简短，特殊确认文案服从项目规范；字级、颜色与间距沿用语义 Token |
| 流程与反馈 | 主路径顺畅，校验时机恰当；加载、空态、成功、失败、禁用、权限变化有完整反馈；错误说明可执行的下一步 |
| 真实数据与视口 | 长名称、大数据、窄屏、弹窗长内容和滚动不遮挡关键操作；保持项目定义的信息密度和布局 |
| 可访问性 | 标签、键盘、焦点进入／返回与错误定位合理；状态不只靠颜色，文字与控件保持可读可操作 |

**反例**：所有错误显示“系统错误”；状态仅一个红点；用加大标题和介绍填充页面；统一封装后丢失列表条件或后台权限。

**正例**：按项目规范显示具体对象／状态，失败说明原因及下一步，重点操作清楚；在真实页面完成查询→编辑→失败恢复→保存→返回的流程，检查滚动、焦点与状态保留。


## 工作流

1. 从真实用户任务识别对象、入口、主路径、失败恢复和完成结果，读项目已确认方案及公共组件。
2. 按矩阵检查真实数据下的页面和全部交互状态；公共组件缺陷优先在公共层修正，并核查调用方原有权限、精度、分页和刷新行为。
3. 对方案问题给出具体场景、影响和建议；改变已确认布局、文案、信息主次或流程时按项目确认机制处理，不自行重设计或重复索取已有效的授权。
4. 在浏览器实际完成任务，检查适用视口、长内容、滚动、键盘／焦点、错误与重试，并遵守项目截图／交互验收门禁；输出证据和未验证项。静态检查、场景作答或截图存在不等于交互／视觉通过。

## 输入与输出

输入：界面实现、设计依据或体验反馈。输出：按任务可判断的改进、真实交互／视觉验证与必要待决项，不把内部技术说明放进产品流程。

## 自检

- [ ] 业务文案与语义样式一致，信息结构、重点及主要操作清楚。
- [ ] 主路径、加载、空态、失败、权限、重试与输入保护完整。
- [ ] 公共组件／Token和项目确认规则已遵守，无擅自改流程。
- [ ] 有适用浏览器证据；静态或未执行部分明确记录。
