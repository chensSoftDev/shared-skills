# 逻辑验证流程指南（Validation Agent）

本指南帮助Agent理解和执行选股验证的完整工作流。

## 核心职责

当用户提交"某支股票，帮我验证买入逻辑"或筛选结果需要验证时，本Agent负责：

1. **基础检查** — 检查流动性、风险等基本条件
2. **逻辑验证** — 对标"验证清单"逐一检查
3. **风险评估** — 计算风险等级和建议止损
4. **生成报告** — 输出验证报告和最终判决
5. **数据更新** — 将通过验证的标的加入候选库

## 验证工作流

### Stage 1: 基础信息收集

**输入**：股票代码或名称 + 用户的买入理由

**操作**：
```
检查项                    操作方法
─────────────────────────────────────────
基本信息                  查询交易所数据
代码和名称                对比证券系统
流动性指标                获取最新行情（成交量/换手率）
重大风险因素              查询公告（退市/违规/股权异常等）
```

**输出**：
```
✅ 基本信息完整
✅ 流动性充足
✅ 无硬性风险
```

### Stage 2: 逻辑完整性评估

**输入**：用户提供的"买入理由"

**操作**：按逻辑验证清单逐项检查
```
□ 买入理由是否清晰？
  判断：理由是否可以用一句话表述，是否基于具体数据而非感性
  
□ 是否有时间锚点？
  判断：理由中是否包含"最近""刚好""今天"等时间指向
  
□ 至少有一个维度的支撑吗？
  判断：理由涉及技术面/基本面/题材面中的至少一个
  
□ 理由与当前价位的关联？
  判断：理由能否解释"为什么现在买"而不是"早点不买"
```

**评分**：
```
所有项都满足 → ✅ 完整（Ready）
部分项不够明确 → ⚠️ 缺陷（Conditional）
多个项不满足 → ❌ 不满足（Unqualified）
```

### Stage 3: 风险因素识别

**输入**：标的基本信息 + 当前市场环境

**操作**：识别和评估潜在风险
```
风险类型              评估方法
─────────────────────────────────
基本面风险           PE/PB/PEG是否合理
题材延续性           题材是否可持续，是否有政策风险
技术面风险           下一个支撑位在哪，跌破风险
个股特殊风险         股权/管理层/竞争等
流动性风险           日均成交量是否充足
```

**输出**：
```
风险等级评分：____分（1-10）
  低风险（1-3分）/ 中风险（4-6分）/ 高风险（7-10分）

主要风险因素：
  - [风险1] 理由和建议
  - [风险2] 理由和建议
```

### Stage 4: 止损和止盈设置

**输入**：买入理由 + 风险等级

**操作**：
```
根据买入逻辑类型确定止损方式：

买入逻辑类型          推荐止损方式          推荐止损幅度
─────────────────────────────────────────
技术突破型            技术位或%止损          3-5%
基本面低估型          %止损                  5-8%
题材热点型            事件止损或%止损        5-10%
反转型                严格%止损              3-5%

止盈设置：
- 基于技术压力位：如"到XX压力位附近逐步卖出"
- 基于目标收益：如"5%收益止盈30%，后续让利润奔跑"
- 基于风险收益比：预期收益/风险 > 1.5
```

**输出**：
```
建议止损位：X.XX元（或Y%）
建议止盈位：X.XX元（或Y%）
风险收益比：Z:1
止损条件描述：清晰的触发条件
```

### Stage 5: 执行可行性检查

**输入**：用户的投资计划

**操作**：
```
□ 拟投入仓位是否合理？（建议单只 5-10%）
□ 最大亏损是否在承受范围内？
□ 建仓时机是否明确？（今天/本周/其他）
□ 监控计划是否可行？
□ 入场和退出条件是否明确？
```

**输出**：
```
资金规划：✅ 可行
入场计划：✅ 明确
监控计划：✅ 可行
```

### Stage 6: 综合判定和输出

**综合评分表**：
```
项目                权重    得分
─────────────────────────
基础信息检查         20%     __/20
逻辑完整性检查       40%     __/40
风险认知检查         25%     __/25
执行可行性检查       15%     __/15
─────────────────────────
总分                100%     __/100
```

**判定标准**：
```
80分+ → ✅ 完整（Ready）
60-80分 → ⚠️ 缺陷（Conditional）
<60分 → ❌ 不满足（Unqualified）
```

**最终输出**：
```
状态：[✅完整 / ⚠️缺陷 / ❌不满足]
理由：[简述主要缺陷或亮点]
建议：[后续操作建议]
```

## 验证决策树

```
入口：用户提交验证请求
  ↓
[基础检查] — 是否有硬性风险？
  ├→ 是 → ❌ 排除
  └→ 否 → 继续
  ↓
[逻辑评估] — 理由是否清晰且有支撑？
  ├→ 完全清晰 → 继续（+1.0倍权重）
  ├→ 基本清晰 → 继续（+0.8倍权重）
  └→ 模糊不清 → ⚠️ 标记缺陷
  ↓
[风险评估] — 风险等级？
  ├→ 低风险 → 继续
  ├→ 中风险 → 标注风险提示，缩小建议仓位
  └→ 高风险 → ⚠️ 强烈风险提示
  ↓
[止损检查] — 止损是否明确合理？
  ├→ 是 → 继续
  ├→ 部分明确 → ⚠️ 要求补充
  └→ 不明确 → ❌ 要求重新定义
  ↓
[综合判决]
  ├→ ✅ 完整 → 加入候选库（状态：ready）
  ├→ ⚠️ 缺陷 → 加入候选库（状态：conditional）+ 标记缺陷项
  └→ ❌ 不满足 → 不加入或标记为观察
```

## 常见情景处理

### Scenario 1: 理由明确但数据支持不足

**现象**：用户理由清晰，但我方查证的数据与其表述不一致

**处理**：
1. 列出数据差异
2. 询问用户是否有我方未获取的信息
3. 标记为"⚠️缺陷"，建议用户补充数据源
4. 可作为"观察中"状态加入候选库

### Scenario 2: 技术强但估值高

**现象**：技术面突破明确，但PE远高于行业均值

**处理**：
1. 标注风险等级为"中高"
2. 要求用户说明是否理解风险
3. 建议缩小仓位或设置更严格的止损
4. 加入候选库但标注"高估值风险"

### Scenario 3: 基本面强但无近期催化

**现象**：公司基本面优秀，但"为什么现在买"的理由不清

**处理**：
1. 标记为"缺乏时间锚点"
2. 询问用户是否有近期催化（如被低估被发现、产业景气等）
3. 如确无催化，建议作为"长期持仓备选"而非"短期建仓"
4. 可加入但状态标记为"conditional"或"observing"

### Scenario 4: 题材驱动但涨幅已大

**现象**：题材相关的涨停股已有多只，该股涨幅已20%+

**处理**：
1. 评估补涨空间是否仍存在
2. 提示题材可能处于"升温"或"高潮"阶段
3. 建议用户等待更好的入场点或规避此标的
4. 风险等级升级为"高"

## 常见缺陷项和改进建议

| 缺陷项 | 示例 | 改进建议 |
|--------|------|--------|
| 缺乏时间锚点 | "早就看好这只股" | 补充"最近XX事件使其被低估"等具体时间参考 |
| 止损不明确 | "赔不起就卖" | 改为"跌破X元"或"亏损超5%"等具体条件 |
| 止盈无规划 | "能涨多高就卖多高" | 改为"到XX位置卖30%，后续看走势"等分阶段计划 |
| 风险认知不足 | 对潜在风险未提及 | 补充主要风险因素的认知和应对 |
| 仓位过大 | "准备重仓" | 建议根据风险等级调整，高风险应缩小仓位 |

## 与其他Agent的协作

### 与筛选Agent的协作

筛选Agent输出的候选 → 验证Agent进行逻辑验证 → 输出验证报告

### 与风控Agent的协作

验证Agent识别风险 → 风控Agent提供详细的风险评分和建议 → 共同输出风控建议

## 验证效率建议

- 对批量候选进行验证时，可按"风险等级"分组处理
- 低风险候选可加快验证速度
- 高风险候选需要更细致的验证
- 可使用"快速验证"（15分钟）和"深度验证"（1小时）两种模式
