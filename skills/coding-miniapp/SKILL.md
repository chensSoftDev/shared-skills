# 小程序端编码规则

## 角色

约束 `miniapp/` 下原生微信小程序 WXML、WXSS、JS 的实现方式，确保新功能和修复符合项目的安全、交互、展示与库存一致性要求。

## 约束

### 通用安全约定

- 不在代码中写死生产密钥，敏感配置从环境变量注入。
- 角色鉴权在服务端执行，前端只消费授权结果。
- 所有写操作必须记录审计日志。
- 每次新增功能、接口或关键业务流程时，必须评估是否需要补充操作日志；涉及库存、配置、权限等变更默认优先考虑记录。
- 出入库操作必须使用事务，保证库存与日志一致。

### 小程序专项

- 新增或修改页面 UI 前必须先阅读 `DESIGN.md`，保持库存管理工具风格一致。
- API 基址由 `miniapp/app.js` 按 `envVersion` 自动切换，禁止硬编码地址。
- 类别/零件选择使用点击弹层列表，不使用 picker。
- 编辑页删除操作必须有二次确认。
- 数量展示去掉无效尾随零，例如 `2.00` 显示为 `2`，`2.10` 显示为 `2.1`。

## 工作流

### 1. 识别变更范围

- 确认用户请求是否涉及 `miniapp/` 下页面、组件、工具函数或小程序配置。
- 若变更触及接口调用、库存、权限或配置，标记为需要额外安全和一致性检查。

### 2. 读取上下文

- UI 变更先读取 `DESIGN.md`。
- API 相关变更检查 `miniapp/app.js` 中的环境切换方式。
- 数量、库存、出入库相关变更确认展示格式和事务要求。

### 3. 实施变更

- 按现有页面和组件模式修改 WXML、WXSS、JS。
- 删除或不可逆操作保留二次确认。
- 新增写操作时同步考虑审计日志、事务和服务端鉴权配套。

### 4. 验证结果

- 检查是否存在硬编码 API 地址、密钥或环境信息。
- 对 UI、数量展示、删除确认、类别/零件选择等关键行为做针对性验证。

## 输入

- 用户指定的小程序功能、Bug、页面或交互变更。
- 可选的目标文件路径，默认关注 `miniapp/`。

## 输出

- 符合小程序端约束的代码变更。
- 必要时说明需要服务端配合的鉴权、审计日志、事务或接口调整。

## 自检

- [ ] `miniapp/` 代码未硬编码 API 地址、生产密钥或敏感配置。
- [ ] UI 变更已对齐 `DESIGN.md`。
- [ ] 删除或不可逆操作有二次确认。
- [ ] 数量展示已去掉无效尾随零。
- [ ] 写操作已评估审计日志、事务和服务端鉴权要求。
