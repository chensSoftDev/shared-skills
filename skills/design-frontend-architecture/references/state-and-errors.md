# 前端业务状态与错误

## 1. 状态归属与异步时序

每项可变状态明确事实源、所有者、作用域、更新入口、持久化和失效时机。能由其他状态推导的值直接推导，不用 effect 维护副本。

| 状态 | 默认归属 | 必须明确 |
|---|---|---|
| 服务端数据 | 已有请求／缓存层 | 查询键含所有生效条件及必要用户范围；变更后的失效、刷新或更新 |
| URL 可分享状态 | 路由参数 | 与筛选／页码单向同步规则，默认值和非法参数处理 |
| 原始表单输入／业务草稿 | 各阶段一个事实源 | 原始字符串可归Form；业务草稿默认归任务对象，明确转换边界，初值／dirty／失败保留 |
| 临时交互 | 最近公共组件 | 展开、选择、焦点等的拥有者和重置条件 |
| 跨页面业务／会话 | 明确范围的 Context／store | 为什么需要跨页、登录／登出／权限变化后的清理 |

- 按项目交互区分“草稿筛选”与“已提交筛选”，不得把已确认的提交式查询悄悄改成逐字即时查询。
- 请求取消或序列／身份校验应保证旧响应不覆盖新条件；卸载后清理订阅、定时器与请求。取消不显示为普通业务失败。
- 保存成功后按数据关系更新／失效缓存，避免刷新整个应用；失败保留输入与可重试上下文。
- 连续点击、切换对象、并发保存和返回列表时的状态需定义。前端防重复提交与服务端幂等配合；写请求超时可能已提交，应先按业务契约核对结果再重试。
- 服务端渲染期间的用户数据不得放入跨请求共享的可变单例；用户切换时隔离缓存。

用互斥状态避免不可能的布尔组合，示意：

```ts
type SaveState =
  | { status: 'idle' }
  | { status: 'saving' }
  | { status: 'failed'; message: string }
  | { status: 'saved'; id: string };
```

## 2. 请求、类型与错误边界

API DTO 描述传输契约，表单模型表达可编辑草稿，展示模型表达 UI 语义；字段相同可复用，日期、单位、空值和可选字段语义不同时显式转换。`unknown` 在边界收窄，避免 `as T` 把未经检查的 JSON 变成可信业务类型。明确缺失、null、空字符串与零的区别；关联 ID、枚举和联合类型不滥用自由字符串。

| 失败 | 处理位置 | 用户结果 |
|---|---|---|
| 字段校验 | 表单字段／提交结果映射 | 就地说明、聚焦错误，保留其余输入 |
| 预期业务失败／冲突 | 业务编排 | 展示具体原因、刷新／修改／重试路径 |
| 网络／超时 | 请求层分类，调用方决定恢复 | 保留上下文，按幂等和结果不确定性决定重试 |
| 登录过期／无权限 | 现有认证与权限边界 | 按项目机制恢复登录或说明权限，防止重试循环 |
| 未知故障 | 任务／诊断边界保留cause，UI适配器负责渲染降级 | 安全反馈及可恢复入口，不暴露内部实现 |

底层保留错误码、可安全展示的信息、必要定位和 cause，界面使用集中映射或项目约定，不直接展示堆栈、SQL 或内部字段。明确由谁提示和上报，避免每层重复 toast／日志。渲染异常由框架适配边界处理；业务命令及异步请求仍显式处理。页面加载失败与空列表是不同状态。

**反例**：`catch { return []; }`；保存无论成功失败都在 `finally` 关闭并 reset 表单。

**正例**：请求失败保留失败状态；仅成功分支关闭表单并更新列表。字段错误映射表单，未知错误保留关联标识并提供恢复入口。

## 3. 表单模式

- 编辑、创建及对象切换明确模型初始化和重置；服务端刷新不覆盖用户未保存草稿。
- 前端校验改善反馈，服务端仍校验和授权；转换与校验集中，金额、数量、日期按契约保留单位／精度／时区。
- 提交状态阻止重复操作，失败保留内容；提交成功后定义关闭、列表刷新、选择与页码结果。
- dirty 基于真实可编辑内容变化；关闭、返回、切换对象按项目规则保护输入。避免用 `JSON.stringify` 任意对象比较代替明确语义。
- 复用已有表单容器／字段，不把复杂业务条件藏入共享表单基类。


业务任务对象统一处理命令状态、请求身份及领域错误，UI适配层将其映射为可见反馈；不在多个Hook和组件重复同一规则。业务草稿归对象时Form由快照受控驱动；若原始输入需保留暂时非法文本，则原始文本归Form，提交／校验边界生成业务对象，两个阶段语义明确，禁止无条件双向同步。
