# NestJS 服务端代码设计规范

## 角色

以后端架构师视角约束模块职责、业务规则、状态、错误和数据库边界，保持安全、一致性与可验证的效率。目标架构用于新增和实质修改代码；按复杂度选用分层，不自动开展存量重构。

## 上下文与配置

先读消费项目 AGENTS.md 与 `.agents/skills-config.json` 的 `coding.nestjs`：`paths` 定义服务范围，`conventions` 定义身份字段、网关／权限、精度、审计等项目差异，`verifyCommands` 提供检查入口。既有键保持兼容，新增约定可选；缺少配置时检查项目与邻近代码，不套用其他项目身份模型、两位小数、目录或部署默认值。源码／文档路径相对消费项目根目录，本文参考相对 skill 目录；框架／ORM 版本读取项目依赖。

代码设计和修改前必读 [references/design.md](references/design.md)，按实际影响选读其中接口、状态、错误、数据库和示例章节。

## 约束

- Controller 负责传输与边界校验，应用服务编排用例，业务规则在内聚业务对象／服务维护，持久化细节有明确归属。简单 CRUD 保留直接清晰的结构，复杂场景再引入独立领域和端口，不机械增加空层。
- 通过封装、依赖注入、小接口与组合隔离变化；明确模块公开能力，避免万能 Service、通用 CRUD 基类、循环依赖与跨模块直读内部表。
- 请求 DTO、持久化 Entity 与响应契约职责明确；运行时校验与字段白名单生效，更新区分缺失、清空与零值。非公开接口默认鉴权，并检查对象／字段级权限；操作人由可信认证上下文统一提取，按项目身份约定兼容。
- 业务状态与合法迁移集中维护，持久状态、请求上下文与缓存分开；共享单例不能保存请求／用户私有状态。并发控制与幂等由数据库约束、原子操作和用例边界共同保证。
- 异常分类、稳定错误码与传输映射明确；禁止把失败变为空结果／成功，禁止暴露堆栈、SQL、凭据等内部信息。错误原因和关联标识在适当边界保留，避免逐层重复日志。
- 配置与凭据使用项目环境入口，不硬编码生产密钥、域名或存储凭据。
- 数据库输入参数化、动态字段白名单、读写权限范围与有界查询是必选要求；性能按实际 SQL、数据规模和测量判断，不用全列索引／缓存掩盖设计问题。

### 迁移、精度、审计与事务

- 生产 schema 通过 migration／SQL／受控数据步骤管理，禁止依赖自动同步；本地 synchronize 成功不证明上线安全。
- Entity、schema、索引／约束、初始化 SQL、RBAC 初始化、历史回填等变化必须评估迁移，并核对初始化入口、已有库基线、预检与回滚。
- 历史库迁移评估幂等及已执行记录；创建表／索引前核对现状，删除索引前检查其是否支撑外键最左列，必要时先建立替代支撑索引。不要只验证空库路径或随意修改已执行 migration。
- 金额、数量、重量、尺寸明确单位、精度、舍入及数据库／JS 表示；精度按字段和项目约定，不把全部 decimal 默认成两位。禁止字符串拼接数字和隐式浮点损失。
- 业务写操作记录审计，关键新流程评估操作日志；操作人、动作、对象和成功事实可追溯，技术日志不能替代审计。事务性业务写入按项目策略保证审计与事实一致。
- 同库多表原子写使用事务，事务内操作使用同一事务 manager／连接；外部系统边界采用明确的一致性策略，不能声称本地事务覆盖远程副作用。

## 工作流

### 1. 定位边界与事实

输入需求、配置与目标模块，读调用方、当前 DTO／Entity／消费契约；输出服务、权限、读写路径、业务状态与迁移影响。字段与 schema 变更先核对生产端及消费端。

### 2. 设计用例

明确公开契约、职责与依赖、状态迁移、授权范围、事务／幂等／并发、错误码及审计点；对数据访问给出查询规模、分页、批处理、索引与验证计划。

### 3. 实现

沿用项目模块与注入方式，把规则放在正确职责内；按设计参考处理 DTO、异常、数据库与迁移。只为具体变化引入抽象，检查所有受影响调用方。

### 4. 验证与交付

按项目配置运行适用 lint、build、测试；对授权、事务回滚、并发不变量、幂等和关键失败路径作必要验证。疑难性能问题检查实际查询／执行计划及代表性数据，数据库测试遵从项目隔离要求。输出代码、迁移／回滚／审计影响及真实结果；未测项明确记录。

## 输入与输出

输入：服务端功能、Bug、接口／数据变更或重构及项目约定。输出：职责、契约、状态、读写和错误边界清晰的实现，必要测试／迁移与验证结果。

## 自检

- [ ] 配置、服务／网关及模块边界正确，无生产配置硬编码。
- [ ] 分层与抽象匹配复杂度，规则内聚，依赖方向清楚。
- [ ] DTO 校验、字段白名单、身份与对象级授权完整。
- [ ] 状态迁移、并发、幂等与事务内数据访问一致。
- [ ] 错误可定位且不泄露，不吞错、不误报成功。
- [ ] 查询有界，N+1／索引／批量写入／事务范围按风险检查。
- [ ] 精度、审计、schema 与数据迁移、回滚已核验。
- [ ] 必要检查及失败路径有真实证据。
