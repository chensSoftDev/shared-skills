# NestJS实现规范

## 角色与上下文

负责NestJS框架落地、项目安全／迁移及验证入口，业务架构与数据库设计由独立规范维护。读取消费项目AGENTS与skills-config的coding.nestjs：paths定义服务，conventions定义网关、身份、权限、精度、审计和异常入口，verifyCommands定义检查。版本和ORM能力读项目依赖，缺配置按真实代码确认，不复制他项目默认值。项目路径相对消费项目根。

## 按改动加载与框架约束

- 业务模块、规则、DTO／契约、状态、错误或数据访问变化时，必读 [design-backend-architecture](../design-backend-architecture/SKILL.md)及其适用参考。环境或框架接线小改按影响选择，不在本入口重复架构正文。
- Module明确exports／imports与provider作用域；通过Nest DI绑定依赖，运行时token／provider显式存在，TS interface本身不是运行时注入token。循环依赖先检查职责，forwardRef不代替边界设计。
- Controller负责传输适配，DTO运行时校验管道需真实生效，核实转换、whitelist及额外字段策略；路径／query／body均处理。业务规则经用例／对象执行，不在Controller直接持久化任意body。
- Guard／认证上下文与项目网关边界一致，非公开接口默认鉴权，操作人按项目约定经显式类型／helper统一提取；对象与字段授权遵从架构规范。
- Entity／Repository是持久化实现，事务manager绑定、响应投影、异常filter／错误码和审计入口复用项目能力并核查其实际行为，不以入口存在声明已经安全。
- 配置／凭据走项目环境入口，不硬编码生产密钥、域名或对象存储凭据；请求私有状态不能保存在共享单例Service字段。

### 迁移、精度、审计与事务

- 生产 schema 通过 migration／SQL／受控数据步骤管理，禁止依赖自动同步；本地 synchronize 成功不证明上线安全。
- Entity、schema、索引／约束、初始化 SQL、RBAC 初始化、历史回填等变化必须评估迁移，并核对初始化入口、已有库基线、预检与回滚。
- 历史库迁移评估幂等及已执行记录；创建表／索引前核对现状，删除索引前检查其是否支撑外键最左列，必要时先建立替代支撑索引。不要只验证空库路径或随意修改已执行 migration。
- 金额、数量、重量、尺寸明确单位、精度、舍入及数据库／JS 表示；精度按字段和项目约定，不把全部 decimal 默认成两位。禁止字符串拼接数字和隐式浮点损失。
- 业务写操作记录审计，关键新流程评估操作日志；操作人、动作、对象和成功事实可追溯，技术日志不能替代审计。事务性业务写入按项目策略保证审计与事实一致。
- 同库多表原子写使用事务，事务内操作使用同一事务 manager／连接；外部系统边界采用明确的一致性策略，不能声称本地事务覆盖远程副作用。

## 工作流

1. 确认服务、版本、网关／身份及受影响框架能力，按表意加载架构与读写规范。
2. 把用例、对象、端口与Nest Module／provider／Controller／DTO／Entity接线，核验校验、鉴权及异常映射实际生效。
3. 对schema／数据变更规划迁移、历史基线、初始化、预检与回滚；写操作配套审计及正确事务绑定。
4. 按项目verifyCommands与实际风险运行lint、build、测试及必要隔离数据库验证，检查调用方，输出真实结果／限制。

## 输入与输出

输入：NestJS实现或框架集成任务。输出：符合项目架构、安全、迁移与验证约定的实现及证据。

## 自检

- [ ] 正确加载适用架构，模块／DI与provider作用域清楚。
- [ ] DTO管道、可信身份、Guard、异常映射及网关约定实际有效。
- [ ] 精度、迁移／回滚、审计与事务manager已核验。
- [ ] 无硬编码生产配置、越界用户状态或未经验证的安全声明。
- [ ] 适用检查及失败路径有真实证据。
