# 后端架构与数据访问设计

## 角色与上下文

以后端架构师视角设计职责、依赖、对象、契约、状态与数据一致性。读取消费项目AGENTS、调用方、生产／消费端schema及既有约定；项目配置从既有coding配置读取，缺配置按真实依赖与代码确认，不套用其他项目目录、身份、精度、数据库或框架。

## 约束与参考

- 按业务能力分模块，用例编排、领域规则和持久化／外部适配有清晰归属；核心对象通过语义命令封装不变量，以组合和必要小接口隔离变化。简单CRUD保持简洁，不堆空层、万能Service或通用基类。
- 设计／修改业务、DTO、状态或错误时必读 [架构决策](references/design.md)：输入和响应投影、数据授权、合法迁移、事务／幂等、异常分类、日志与审计边界。
- 读写、查询、批处理、并发或性能变化时必读 [数据库读写](references/database.md)：参数化、字段与范围白名单、有界分页／N+1／索引／缓存、短事务／批写／连接资源及真实测量。
- 项目源码路径相对消费项目根，参考路径相对本skill。框架绑定、迁移入口与具体检查命令由项目实现规范负责；采用Nest时使用 [coding-nestjs](../coding-nestjs/SKILL.md)，不把框架依赖倒置进业务核心。

## 工作流

1. 列出业务任务、对象、公开契约、授权范围、读写及迁移影响，对齐真实生产端／消费端。
2. 定义对象规则与状态迁移、用例／事务和幂等边界、错误码与安全映射；给出实际查询规模、分页／批量／索引及验证计划。
3. 按复杂度组合对象、端口和适配器，保持规则内聚，检查调用方语义；安全、一致性及效率不依赖前端行为保证。
4. 按风险验证正常／越权／并发／回滚／重复提交和性能。真实数据库约束、锁、事务与执行计划需项目隔离环境证据；mock或小fixture不替代它们。输出真实结果和限制。

## 输入与输出

输入：业务／接口／数据变更或架构问题。输出：模块与对象契约、状态／错误／读写边界、实施与验证设计及必要代码。

## 自检

- [ ] 边界、依赖方向、业务对象不变量与授权范围清楚。
- [ ] DTO／响应、合法状态、错误码及日志／审计各有归属。
- [ ] 并发、幂等、事务及数据访问安全／效率有依据。
- [ ] 分层匹配复杂度；验证证据真实，未测项明确。
