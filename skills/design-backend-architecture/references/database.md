# 数据库读写安全、性能与效率

## 1. 安全与范围

- 值使用参数绑定；表名、列名、排序方向不能用普通值参数代替，必须由服务器白名单映射，禁止拼接用户输入。
- 读、更新、删除、批量操作和计数都使用授权范围，敏感投影也需权限；软删除／有效态按业务统一处理。
- 防止空条件／缺失 ID 扩大为全表读写，批量操作核实范围及行数；高影响更新先明确预期集合和失败策略。
- 数据库账户遵循项目最小权限，迁移权限与日常运行按需要隔离；日志和缓存 key／内容避免泄露敏感数据。

## 2. 查询效率

- 列表服务端过滤、排序、投影与有界分页，不全表读出后内存分页。排序具有稳定次序和唯一的兜底键；深页／大量导出按规模选游标或流式／分块处理，不一律强制改协议。
- 识别循环逐条查询、隐式 lazy relation 和 N+1；按 ID 集合批查或合适 JOIN，注意一对多 JOIN 造成重复、总数失真与分页语义变化。
- 只取必要列／关联，分页和批量大小有限制；空集合不产生意外全表查询。
- 索引根据真实 where／join／order、选择性和数据规模设计，核对复合索引顺序、重复索引、写入代价和外键支撑。不是每列都加索引。
- 热点／疑难查询检查实际 SQL、执行计划和代表性数据下的耗时／扫描行／查询次数；不以少量 fixture 或“用了索引”断言性能。
- 缓存前先明确收益、授权隔离、键、TTL／失效和可接受陈旧性；不为每次读取强制加缓存，不把私有结果跨用户共享。

## 3. 写入与资源效率

- 缩短事务和锁持有时间：事务内只做必要工作；避免无界循环、远程 I/O、等待人工或耗时文件操作。
- 根据驱动参数／包大小和业务原子性分块批写，减少往返；不能用 bulk API 绕过领域校验、审计、hooks／subscriber 或幂等语义。
- 并行访问有界，不用无上限 `Promise.all` 耗尽连接池；核对超时、连接释放、池容量和锁等待。
- 死锁／临时故障只做有限、可观测且满足幂等的重试，事务失败后整体重试；写请求超时可能已提交，先按幂等结果核对，禁止盲目重复副作用。
- 大批迁移／回填评估分块、断点、锁、日志与回滚；执行前遵守项目环境与授权要求。
